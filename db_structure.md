# СТРУКТУРА БД


## Таблица countries (CountryModel)
--- основная таблица с инфой про страны ---
id (str) - кодовое название страны (содержит только буквы и _). Является уникальным идентификатором. 
    Является внешним ключом к таблице country_relations
name (str) - нормальное название страны на русском
parent (str/None) - айдишник страны, которая эта подчинена или в чей состав входит (если не подчинена, то None).
    Является внешним ключом

parent_country (CountryModel/None) - сюда подтягивается связь по ключу parent
children (List[CountryModel]) - сюда подтягивается связь по ключу parent
relation (CountryRelationModel) - сюда подтягивается связь по ключу country_relations.id
periods (List[PeriodModel]) - сюда подтягивается связь по ключу periods.country_id



## Таблица country_relations (CountryRelationModel)
--- минималистичная таблица связей между странами ---
id (str) - то же самое что и id страны. Внешний ключ к таблице countries
before_id (str/None) - айдишник предыдущего исторического периода страны. Внешний ключ к таблице countries
after_id (str/None) - айдишник следующего исторического периода страны. Внешний ключ к таблице countries

now (CountryModel) - сюда подтягивается связь по ключу id
before (CountryModel/None) - сюда подтягивается связь по ключу before_id
after (CountryModel/None) - сюда подтягивается связь по ключу after_id



## Таблица videos (VideoModel)
--- основная таблица с инфой про видео ---
num (int) - номер видео по времени выхода на канале. От 1 и до 300 с чем-то там. Является уникальным идентификатором
name (str) - название видео
link (str) - ссылка на само видео на ютубе
image_file (str) - название файла, где хранится картинка с превью видео
description (str) - краткое описание, что содержится видео
quality (str) - HEX-код цвета качества. Для самого первого видео это "#990000", 
    для большинства видео (всех начиная с какого-то конкретного, которое потом выберу) "#009900",
    для всех остальных это промежуточные значения между ними.
published (Date) - дата публикации

periods (List[PeriodModel]) - сюда подтягивается связь по ключу periods.video_num



## Таблица periods (PeriodModel)
id (int) - уникальный айдишник периода, никакой информационной нагрузки в себе не несёт
video_num (int) - номер видео, к которому относится период. Внешний ключ к таблице videos
country_id (str) - айдишник страны, к которой относится период. Внешник ключ к таблице countries
start (int) - год начала
end (int) - год окончания
is_main (bool) - является ли основным. Если основное то True, если косвенное, то False

video (VideoModel) - сюда подтягивается связь по ключу video_num
country (CountryModel) - сюда подтягивается связь по ключу country_id






# РАБОТА ЗАПРОСОВ


## Запрос /videos/1950?country=pakistan
--- Запрос всех видео, касающихся данной страны в данный год ---

1. Идём в таблицу periods и берём оттуда все периоды, у которых country_id == pakistan, start <= 1950, end >= 1950
2. Проходимся по полученному списку и формируем на его основе массивы main и indirectly в зависимости от значения поля period.is_main, добавляем в этот массив VideoModel из поля period.video, если его там ещё нет

Результат выполнения запроса:
{
    "main": [ массив из VideoModel ],
    "indirectly": [ массив из VideoModel ]
}



## Запрос /videos/1950
--- Запрос всех видео, касающихся данного года ---

1. Идём в таблицу periods и берём оттуда все периоды, у которых start <= 1950, end >= 1950
2. Проходимся по полученному списку и формируем на его основе массивы main и indirectly в зависимости от значения поля period.is_main, добавляем в этот массив VideoModel из поля period.video, если его там ещё нет

Результат выполнения запроса:
{
    "main": [ массив из VideoModel ],
    "indirectly": [ массив из VideoModel ]
}



## Запрос /videos?country=pakistan
--- Запрос всех видео, касающихся данной страны за всю её историю ---
Это сложный запрос, всё предрасчитано и готовый ответ лежит в файлике pakistan.json в специальной папочке precalculated_timelines. Далее описан алгоритм для скрипта предрасчёта.

1. Идём в таблицу countries, проходимся по цепочке из relations.before и по цепочке relations.after, так формируем список айдишников, которые нас интересуют
2. Идём в таблицу periods и берём оттуда все периоды, у которых country_id присутствует в нашем списке и is_main == True (аналогичные действия для is_main == False - тогда будет массив indirectly), получаем список периодов.
3. Сортируем список периодов по возрастанию start.
Массив main состоит из объектов вида {
    start: int,
    end: int,
    videos: List[VideoModel]
}
4. Обход массива периодов. Смотрим, пересекается ли он с каким-то из элементов массива main. Если нет, просто добавляем в конец массива main объект, сформированный на основе нашего. Если полностью совпадает, то просто video из рассматриваемого периода добавляем в массив videos (если там его ещё нет). Если пересекается, то делим на 3 промежутка и соответствующим образом заполняем список видео для каждого.
5. Обход массива main. Для каждого элемента сортируем массив videos чтобы они были по возрастанию num.
6. Обход массива main. Т.к. у нас разные айдишники стран, может получиться несколько периодов подряд с идентичным списком видео. Обходим и сравниваем списки видео соседних периодов. Если совпадают, объединяем в один период.

Результат выполнения запроса:
{
    "main": [
        { "start": 1900, "end": 1904, "videos": [ массив из VideoModel ] },
        { "start": 1905, "end": 1905, "videos": [ массив из VideoModel ] },
        { "start": 1906, "end": 1920, "videos": [ массив из VideoModel ] }
    ],
    "indirectly": [ аналогичный массив ]
}






# РЕАЛИЗАЦИЯ НА ФРОНТЕ

На фронте у нас всегда выбран какой-то год (не может быть не выбран).
Пользователь кликает на страну.
    Первым летит запрос /videos по году+стране. У него более короткая обработка и эта инфа будет отображена первым.
    Сразу же за ним летит запрос /videos только по стране.

В правой части экрана (на телефоне на весь экран) у пользователя открывается окошко, примерно на треть экрана. В нём сверху есть переключатели:
1. Верхний переключатель отвечает за страну. Если выбранное государство является дочерним, то слева название родительского государства, справа дочернего. Выбрано будет название дочернего, можно будет переключиться на родительское. После этого переключения, вид переключателей слегка меняется. Слева всё так же название родительского государства, а вкладка справа называется "регионы". Аналогично выглядит переключатель если изначально пользователь кликнул на родительское государство. Можно перейти на вкладку с регионами и выбрать конкретный, тогда переключатель примет вид описанный ранее. Аналогично меняются контуры выделенной на карте территории
2. Нижний переключатель отвечает за время. Слева номер выбранного сейчас года, справа "вся история". Изначально всегда выбран конкретный год. Там просто у нас есть 2 списка видео: сверху те что "основное", снизу те что "косвенно". Видео представлено названием и небольшой картинкой превью. По нажатии на видео уже в левой части экрана (на телефоне поверх предыдущего) тоже примерно на треть экрана открывается уже инфа о видео, где можно и перейти по ссылке на ютуб. При переключении на "вся история" тоже имеем два блока: сверху основное, снизу косвенно. Но это уже не просто списки. Это последовательность из небольших контейнеров, у которого слева небольшая область с указанием года (например 1918-1922 с переносом строки между ними), а справа большая область по списком видео, соответствующих этой временной области
